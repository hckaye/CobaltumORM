# CobaltumORM のビルド診断

[English](diagnostics.md) | 日本語

ビルドエラーが出たときは、以下からコードを探して原因と対処を確認してください。
各コードの背後にある規則は [quick-reference.ja.md](quick-reference.ja.md)、動作する実例は
[recipes.ja.md](recipes.ja.md) にあります。

これらのコードは 2 つのコンポーネントが報告します。Roslyn のソースジェネレーターは `COB001` から
`COB009` を通常のコンパイラ診断として報告し、それぞれこのページをヘルプリンクとして持ちます。
MSBuild と `cobaltum generate` の中で動くビルド変換は、`COB010` と `COB100` から `COB109` を、ファ
イルと行を伴う MSBuild のエラーとして報告します。こちらにリンクは付きません。

一部のメッセージには SQL 解析器のコードが埋め込まれます。`SQL` はクエリのパーサーとバインダー、
`DDL` はマイグレーションのパーサーが出すコードで、SQL 内の位置を示します。内容はメッセージ本文で
説明されます。

## ソースジェネレーターの診断

### COB001

マイグレーションを安全に解析できません。

ビルドは `Up` をソースとして読み、その操作をメモリ上のスキーマへ適用します。そのため `Up` に書ける
のは、対応しているマイグレーションの呼び出しチェーンとローカルの `const` 宣言だけです。`if`、ループ、
ヘルパーメソッドの呼び出し、対応外のチェーンの起点、`IfDatabase` の述語オーバーロードは、コードを
実行しないと評価できません。

処理を別のマイグレーションへ分けるか、`AdditionalFiles` に追加した Flyway 互換 SQL ファイルとして
スキーマ変更を記述してください。

### COB002

マイグレーションの引数は定数である必要があります。

名前、長さ、精度、位取り、既定値のリテラル、`IfDatabase` のデータベース名、`RawSql.Insert` のテキ
スト、`Execute.Sql` に渡す SQL はビルド時に読み取ります。そのため、コンパイル時定数、`SystemMethods`
の値、`RawSql.Insert` の呼び出しのいずれかである必要があります。空文字列の引数も同じ理由で拒否され
ます。

計算した引数をリテラルか `const` フィールドに置き換えてください。

### COB003

マイグレーションの SQL が不正です。

`Execute.Sql` または Flyway 互換ファイルの SQL が解析できないか、クエリの結果を変えうるスキーマ操作
でコンパイル時解析の対象外です。メッセージには `DDL` コードとパーサーのメッセージが含まれます。

SQL を修正するか、C# マイグレーションの API で同じ変更を記述してください。

### COB004

クエリの SQL が不正です。

`[Query]`、`[Query<T>]`、`Query(...)` の SQL が解析できないか、すべてのマイグレーション適用後に存在
しないスキーマ、テーブル、列を参照しているか、解析対象外の構文を使っています。メッセージには `SQL`
コードと解析器のメッセージが含まれます。

名前か構文を修正してください。対応範囲外の構文であれば
[`NoCheckQuery`](recipes.ja.md#ビルドで検査できない-sql-を実行する) を使います。

### COB005

生成される名前が衝突します。

名前付きクエリが生成するメンバー名が、コンテナークラスに既に宣言されています。

クエリ名か衝突しているメンバー名を変更してください。

### COB006

この宣言はコード生成の対象外です。

マイグレーションまたはクエリコンテナーとして使えない宣言です。マイグレーションは
`CobaltumOrm.Migrations.Migration` を継承した、ジェネリックではない具象クラスで、public な既定コンス
トラクターを持ち、`Up` をソースに直接宣言する必要があります。クエリコンテナーは名前空間直下の
ジェネリックではない `partial class` で、`[Query]` の引数は空でないコンパイル時の文字列定数である
必要があります。

宣言をこの形に合わせてください。

### COB007

生の SQL をコンパイル時に検証できません。

`Query(string)` にコンパイル時に決まらない SQL が渡されました。

SQL を定数にするか、検査しないことを明示するために `NoCheckQuery` を呼んでください。

### COB008

ジェネレーターの設定が不正です。

`CobaltumOrmGeneratedNamespace` がドット区切りの有効な C# 名前空間でないか、
`CobaltumOrmDatabaseProvider` が `PostgreSql`、`MySql`、`Sqlite`、`SqlServer`、`Oracle` のいずれでも
ありません。

プロパティの値を修正してください。どちらのプロパティも、ビルドから読み取れるように
`CompilerVisibleProperty` に列挙する必要があります。

### COB009

クエリの結果型へマッピングできません。

SQL が返す列を `[Query<T>]` または `Query<T>(sql)` で指定した型へマッピングできません。列が足りない、
CLR 型か null 許容性が一致しない、または文が行を返していません。

結果型のコンストラクターまたは書き込み可能なメンバーを、選択した列に合わせてください。
`[ResultColumn("column_name")]` で列名を明示することもできます。

## ビルド変換の診断

### COB010

`cobaltum generate` がソースジェネレーターを実行中に例外が発生しました。

メッセージは例外のメッセージです。これは CobaltumORM の不具合です。再現するマイグレーションとクエリ
のソースを添えて報告してください。

### COB100

`Query` にはコンパイル時定数か、すべての穴が値の位置にある補間文字列が必要です。

SQL を定数にするか、検査しないことを明示するために `NoCheckQuery` を呼んでください。これはビルド
変換における [COB007](#cob007) に相当します。

### COB101

`Query` の SQL を検査対象の文として扱えません。

文の分割に失敗した、文が 1 つも含まれていない、スキーマ変更が含まれている、または行を返す `Query`
に複数の文が含まれています。

1 回の呼び出しにつき 1 文になるよう分け、スキーマ変更はマイグレーションとして宣言してください。

### COB102

行を返さない文に補間文字列の `Query` を使っています。

補間文字列の `INSERT`、`UPDATE`、`DELETE` は受け付けません。

文を固定 SQL で書き、値は `WithParameter` で渡してください。

### COB103

補間の穴の SQL 型を推論できません。

穴が値の位置にないため、パーサーがその穴に対応するパラメーターを作れませんでした。補間はスキーマ名、
テーブル名、列名には展開されません。

SQL の構造はテキストとして書き、名前には `SqlSchema` の定数を使ってください。

### COB104

補間の穴の CLR 型が一致しません。

メッセージには式の型と SQL が要求する型が示されます。両者の間に暗黙の変換がありません。

値を変換するか、穴を比較する列または式を変更してください。

### COB105

`Query` または `NoCheckQuery` の接続の式を解決できません。

ビルド変換は呼び出し箇所を書き換えるため、レシーバーをそのままコピーできる式である必要があります。

複雑な式の結果ではなく、`DbConnection` の変数、フィールド、プロパティに対して呼び出してください。

### COB106

補間の穴に配置指定または書式指定が使われています。

穴は書式化されたテキストではなくパラメーターになるため、`{value,10}` や `{value:d}` は受け付けません。

指定を削除し、C# 側で値を整形して渡すか、SQL 側で整形してください。

### COB107

`WithParameter` の名前が検査対象の SQL と一致しません。

SQL が使う名前付きパラメーターに含まれていない、同じ名前を 2 回束縛している、またはその値を補間の穴
としてすでに渡しています。

SQL に現れるパラメーター名を、それぞれ 1 回ずつ使ってください。

### COB108

`WithParameter` の値の CLR 型が一致しません。

メッセージには値の型と SQL が要求する型が示されます。両者の間に暗黙の変換がありません。

渡す前に値を変換してください。

### COB109

クエリの結果を指定した型へマッピングできません。

行を返さない文に `Query<T>` を使っているか、返る列が `T` のコンストラクターまたは書き込み可能な
メンバーと一致しません。`NoCheckQuery<T>` では、`T` 自体の構造をマッピングできない場合に同じコード
を報告します。

`T` を選択した列に合わせるか、`[ResultColumn("column_name")]` で列名を明示するか、行を返す文を選んで
ください。これはビルド変換における [COB009](#cob009) に相当します。
